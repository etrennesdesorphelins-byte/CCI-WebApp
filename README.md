# 歩行筋電図 共同収縮指数（CCI）解析 Web アプリ

歩行周期に時間正規化した4筋（RF・BF・TA・Gas）の筋電図から、**RF–BF** と **TA–Gas** の共同収縮指数（CCI）を、歩行周期全体（GC）と4つの歩行相（LR / SLS / PSw / Sw）について計算します。結果は表と波形グラフで表示し、CSV・Excel・PNG で保存できます。

- 仕様の一次資料：[CCI_Requirements_Definition.md](CCI_Requirements_Definition.md)（要件定義書）、[CCI_Technical_Proposal.md](CCI_Technical_Proposal.md)（技術提案書）
- **ファイルはブラウザ内だけで処理します。** サーバー・外部 API・外部 AI へは送信しません（バックエンドなしの静的サイト）。

## 使い方

1. アプリを開き、`.xlsx` または `.csv` をドラッグ＆ドロップ（またはクリックして選択）します。
2. 「シート・列の対応」で対象シート、ヘッダー行の有無、時間軸、各筋の列を確認します（初期値：A=歩行周期、B=RF、C=BF、D=TA、E=Gas、先頭行=ヘッダー）。
3. 「入力プレビュー」で行数・歩行周期の範囲・エラーを確認します。
4. 「解析設定」で歩行相の境界を確認・編集し、**解析** を押します。解析後に境界を変更すると自動で再計算されます。
5. 結果表の行や「強調区間」ボタンで区間を選ぶと、グラフ上でその区間と重複領域が強調されます。
6. CSV・Excel・PNG で保存します。

画面上の「合成サンプル」から、動作確認用のデータ（実在の被験者データではありません）を読み込めます。

## 計算方法（変更不可の確定仕様）

区間 `[s, e]` における 2 筋の筋活動 `a(t)`, `b(t)` について

```
CCI_[s,e] = 100 × 2∫_s^e min(a(t), b(t)) dt / ∫_s^e (a(t) + b(t)) dt   [%]
```

| 項目 | 内容 |
|---|---|
| 対象ペア | RF–BF、TA–Gas |
| 積分 | サンプル間を線形補間した区分線形関数を台形則で積分（区分線形関数に対して厳密） |
| 波形の交点 | サンプル間で 2 波形が交差する場合は交点を挿入して `min(a,b)` を積分 |
| 相境界 | サンプル位置と一致しない境界（例：12.5%）は線形補間点を挿入して区切る |
| 分母が 0 | `N/A`（0% や NaN にしない）。理由を併記し、他の結果は表示 |
| 丸め | 表示のみ小数第 2 位。内部計算・CSV/Excel のセル値は丸めない |
| 全周期 CCI | GC 区間を直接積分（相別 CCI の平均ではない） |
| 振幅 | 入力値をそのまま使用。**アプリ側で再正規化・平滑化・整流は行わない** |

> CCI には複数の定義があります。研究報告では上記の式そのものを明記してください。また、入力は各筋の歩行周期平均値で正規化済みであることを前提とし、筋ごとに異なる基準で正規化することは CCI の値に影響し得ます。

実装は [src/services/cci.ts](src/services/cci.ts)（React に依存しない純粋関数）です。

## 歩行相の初期境界

| 区間 | 略号 | 初期値 |
|---|---|---|
| 歩行周期全体 | GC | 0–100% |
| 荷重応答期 | LR | 0–10% |
| 単脚支持期（立脚中期＋立脚終期） | SLS | **10–50%** |
| 前遊脚期 | PSw | 50–60% |
| 遊脚期 | Sw | 60–100% |

- 編集できるのは LR終了・SLS終了・PSw終了 の 3 境界で、`0 < LR終了 < SLS終了 < PSw終了 < 100` を満たす必要があります。「初期値に戻す」で 10 / 50 / 60% に戻ります。
- **固定した % は標準的な時間配分による便宜的な初期値です。** 被験者の実際の接地・離地イベントから判定した単脚支持期ではありません。脳卒中歩行などでは実測イベントに合わせて変更してください。

## 入力データ

- 1 ファイル（1 シート）＝ 1 試行の歩行周期正規化波形。
- 4 筋の値は 0 以上の有限な数値（0 は可）。
- 時間軸（「時間軸」設定）
  - **自動（既定）**：時間列が有効な 0〜100%（単調増加・重複なし・両端 0 と 100 を含む）ならその値を使用。無効（行番号など）または空で、データが **101 行** なら行順に 0, 1, …, 100% を割り当て。
  - **時間列の値を使用**：時間列が不正ならエラー。
  - **行順に割当**：101 行の場合のみ。
  - 101 点以外のデータは、有効な時間列がある場合のみ解析できます（不等間隔も可）。
- 以下はエラーとして行番号・筋名・列を表示し、解析を止めます：列不足、欠損（空欄）、非数値、負値、無限大、時間列の降順・重複・範囲外、Excel の未計算の式（キャッシュ値がない式セル）、Excel のエラー値。
- 上限 20 MB。壊れたファイル・旧 `.xls` はエラーメッセージを表示します。
- CSV は UTF-8（BOM 有無とも）と Shift_JIS（Windows 版 Excel の CSV）に対応します。

## 出力

| 形式 | 内容 |
|---|---|
| CSV | `source_file, sheet, pair, phase, start_percent, end_percent, cci_percent, na_reason, calculation_method, integration_method, normalization_method, analyzed_at`。N/A は `cci_percent` を空欄にし、`na_reason` に理由。Excel で開けるよう UTF-8 BOM 付き |
| Excel | `CCI_Results` シート（表示は 0.00 書式、値は丸めなし）、`Settings` シート（計算式・積分法・正規化・ペア・列対応・時間軸・各相の境界・入力ファイル名・解析実行日時〔端末時刻〕） |
| PNG | 各ペアのグラフ。タイトルにペア名・選択区間・境界・CCI・ファイル名、凡例に筋名、軸名を含む |

元の筋電データを Excel 出力に含める機能は将来対応です。

## 未確定事項と初期実装の仮定

実データ受領時に確認します。現時点では以下を仮定して実装しています（計算方式は変更していません）。

| 項目 | 初期実装の仮定 |
|---|---|
| A 列の内容 | 0〜100% として有効なら歩行周期として使用。行番号・空欄などで 101 行なら 0〜100% を自動割当 |
| ヘッダー行 | あり（切替可） |
| 複数シート／複数試行 | 1 シート＝1 試行。シートは選択可。複数試行の一括処理は対象外 |
| BF・Gas の筋頭・左右 | 元データの定義に従う（アプリは列ラベルを表示するのみ） |
| 筋ペア | RF–BF、TA–Gas の 2 ペアのみ（[src/domain/types.ts](src/domain/types.ts) の `DEFAULT_PAIRS` で拡張可能な構造） |
| CCI の定義 | 上記の重複面積型のみ。既存研究の値と一致させる場合は、計算式と前処理の一致を最優先で確認すること |
| 相境界 | 時間割合による手動指定。実測イベント（対側離地・対側接地・同側離地など）からの自動設定は対象外 |

## 開発

```bash
npm install
npm run dev        # 開発サーバー
npm test           # Vitest（CCI 計算・境界・入出力・異常系）
npm run build      # 型チェック + 本番ビルド（dist/）
npm run preview    # ビルド結果をローカル表示
node scripts/generate-samples.mjs   # 合成サンプルの再生成
```

技術スタック：React + TypeScript、Vite、ExcelJS（xlsx 読込・出力）、Papa Parse（CSV）、Plotly.js（basic ビルド、グラフ・PNG 出力）、Vitest。

```
src/
  components/   画面（FileUpload, ColumnMapping, DataPreview, PhaseEditor, ResultsTable, EmgChart, ChartsSection, ExportPanel）
  domain/       型・筋ペア・歩行相の定義
  services/     cci（計算）, parsers（読込）, validation（検証）, export（出力）
  hooks/        useAnalysis（画面状態と計算の接続）
  tests/        自動テスト
```

## GitHub Pages への公開

1. GitHub にリポジトリを作成し、`main` ブランチに push します。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. `main` への push ごとに [.github/workflows/deploy.yml](.github/workflows/deploy.yml) が `npm ci` → テスト → ビルド → Pages へのデプロイを行います。`base` は `/<リポジトリ名>/` に自動設定されます（ユーザーサイト `<user>.github.io` の場合は workflow の `VITE_BASE` を `/` に変更）。
4. 公開 URL（`https://<user>.github.io/<repo>/`）で AT-11（読込・解析・保存）を確認します。
